## 二、核心模块说明

### 1. 数据接入层
- **Kafka**：接收气象站、逆变器、电表的实时数据流
- 三个Topic：`weather_raw`、`inverter_raw`、`meter_raw`
- 支持多消费者组，数据不丢失

### 2. 数据存储层
- **InfluxDB**：时序数据库，存储预测/实际功率、气象数据、设备数据
- **MinIO/S3**：对象存储，归档原始Kafka消息、模型文件、训练报告
- 冷热分离：InfluxDB存热数据（近30天），S3存冷数据（历史归档）

### 3. 数据处理层
- **数据清洗**：异常值检测（3σ+业务规则）、缺失值填充（时间插值）
- **时间戳对齐**：多源数据按15分钟重采样对齐
- **特征工程**：
  - NWP气象特征：GHI、温度、湿度、云量、风速
  - 历史功率特征：滞后特征（lag_1/2/4/8/24/48/96）、滑动窗口统计（均值/标准差/最大值）
  - 日历效应特征：小时/月份/年内天数的正余弦编码、是否白天
  - 物理衍生特征：太阳高度角、斜面辐照度估算、温度修正因子

### 4. 模型层
- **物理模型**：新建园区冷启动，无需训练，基于辐照度-温度-效率公式
- **XGBoost**：工业基线，梯度提升树，稳定可解释
- **LSTM**：时序深度学习，捕捉时序依赖
- **Transformer**：先进模型，自注意力机制捕捉长程依赖
- **模型选型**：按NMAE（60%权重）+ 合格率（40%权重）综合评分，自动选最优

### 5. 调度优化层（MPC）
- 基于光伏预测结果，优化储能充放电策略
- 目标函数：最小化（购电成本 - 售电收入 + 储能损耗成本）
- 约束条件：
  - 功率平衡：光伏 + 购电 + 放电 = 负荷 + 充电 + 售电
  - SOC动态：SOC(t+1) = SOC(t) + (充电×η_ch - 放电/η_dis) × Δt
  - SOC上下限：20%~80%
  - 电网功率：购电≤2000kW，售电≤1000kW
- 求解器：Gurobi（商业，需license）/ PuLP+CBC（开源，默认）
- 兜底策略：求解器不可用时使用启发式策略（谷充峰放、富余光伏充电）

### 6. 服务层
- **FastAPI**：高性能异步Web框架
- 核心接口：光伏预测、MPC优化、模型管理、监控
- 自动生成Swagger文档
- 支持CORS、全局异常处理、请求计时中间件

### 7. 部署与监控层
- **Docker**：多阶段构建，优化镜像体积
- **K8s**：Deployment + Service + ConfigMap + Secret + PVC + HPA
- **Prometheus**：采集服务指标（请求量、响应时间、NMAE、合格率）
- **Grafana**：实时监控看板（预测vs实际、精度趋势、系统资源）
- **定期重训练**：APScheduler按cron表达式每周自动重训练，自动切换最优模型

## 三、数据流

### 实时数据流
```
传感器 → Kafka → 消费者 → InfluxDB(实时查询) / MinIO(归档)
```

### 预测数据流
```
天气预报API → 特征工程 → 模型预测 → 物理约束 → InfluxDB(存储) / API(下发)
```

### 训练数据流
```
InfluxDB(历史数据) → 数据清洗 → 特征工程 → 模型训练 → 评估对比 → 模型存储 → 激活切换
```

### MPC调度数据流
```
光伏预测 + 负荷预测 + 电价 → MPC优化器 → 储能充放电计划 → EMS/SCADA执行
```

## 四、扩展性设计

1. **模型扩展**：继承`BasePVModel`基类，实现`train/predict/save/load`四个方法即可接入新模型
2. **数据源扩展**：Kafka消费者支持多Topic，新增数据源只需添加Topic和处理逻辑
3. **求解器扩展**：MPC优化器支持Gurobi/PuLP双引擎，可扩展其他求解器
4. **部署扩展**：K8s HPA支持根据CPU/内存自动扩缩容
